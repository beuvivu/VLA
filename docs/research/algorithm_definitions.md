# Algorithm Definitions and Scientific Contracts

Verified: 2026-09-02

## 1. Probability versus score

A calibrated model output may be called a probability only when its probability
contract is explicit and evaluated with proper scoring rules. An arbitrary
weighted index is a **score**, not a probability.

Primary predictive losses:

- Brier: `mean((p-y)^2)` for Bernoulli targets;
- Loto LogLoss: mean binary cross-entropy over the 100 candidate marginals;
- Đề: exactly one of 100 numbers is correct, so VLA normalizes a 100-number vector
  and evaluates categorical LogLoss plus multiclass Brier.

Both metrics are losses: lower is better.

`skill = (baseline_loss - challenger_loss) / baseline_loss`.

Positive skill is improvement; zero is no improvement; negative skill is degradation.

## 2. Temporal contract

For prediction target date D every feature must be computable using information
available strictly before D. If anchor date is t and target is t+1, same-anchor
features may use results through t but never target t+1.

A draw/date is one temporal cluster. All 100 candidate rows for a date must stay in
the same train/calibration/test partition.

Future-mutation invariant:

1. build features through historical cutoff D;
2. alter raw results strictly after D;
3. rebuild all features;
4. every feature for anchors <=D must be bitwise/equivalently unchanged.

Failure is temporal leakage and blocks production.

## 3. Canonical two-digit ontology

The source of truth is `src/number_reference.py`.

For AB:

- head = A;
- tail = B;
- reverse/lộn = BA;
- digit total modulo 10 = `(A+B) mod 10`;
- chạm d = numbers containing digit d in either position;
- bóng dương digit mapping = 0<->5, 1<->6, 2<->7, 3<->8, 4<->9;
- bộ = orbit generated by digit-wise bóng dương and reversal;
- cặp 50 = 45 non-double reverse pairs plus 00-55, 11-66, 22-77,
  33-88 and 44-99.

Same-draw statistical co-occurrence is a different object from a deterministic
number-domain pair.

## 4. Frequency

For number x and an eligible window W:

`occurrence_count(x,W) = sum_d count_x(d)`

`draw_count(x,W) = sum_d 1[count_x(d) >= 1]`

`draw_hit_rate(x,W) = draw_count / |W|`.

The occurrence and draw-count quantities must be exposed separately because a
number can occur more than once in one XSMB draw.

## 5. Gap / lô gan

For target D:

`gap(x,D) = elapsed completed eligible dates/draws since the most recent hit of x before D`.

VLA records the unit explicitly where calendar gaps are used. Current gap is a
descriptive state, not evidence that a future hit is "due".

Useful historical summaries include max/mean/median gap, empirical quantiles and
the current right-censored interval.

## 6. Recurrence/cycle

For occurrence dates `d1 < ... < dn`, completed intervals are
`g_i=d_i-d_(i-1)`. The current interval from the latest hit to the as-of date is
right-censored and should be reported separately rather than silently pooled with
completed intervals.

## 7. Pair statistics

For unordered numbers i != j and N eligible dates:

`cooccur(i,j) = count(dates where i and j both occur)`

`support = cooccur/N`.

Optional Jaccard and phi capture same-draw association. Raw counts/support remain
necessary even when normalized association metrics are emitted.

## 8. Conditional association

For event A at t and event B at t+1:

`support(A->B) = count(A_t and B_t+1) / N_eligible`

`confidence(A->B) = count(A_t and B_t+1) / count(A_t)`

`lift(A->B) = confidence / P(B)`.

Small-sample probabilities should be shrunk toward a marginal prior. Exact +1
calendar-day transitions are required for "next-day" semantics.

## 9. Markov

For categorical states and smoothing alpha:

`P_ij = (count(i->j)+alpha) / (sum_k count(i->k)+alpha*|S|)`.

For binary per-number hit/miss states, Beta smoothing is the corresponding
special case. Second-order states require sufficient support and aggressive
shrinkage. Markov outputs remain research evidence until they beat simple
marginal/rolling baselines on temporal OOS loss.

## 10. Dynamic positional cầu

A semantic source position is `(prize_name, result_index, digit_index)` rather
than a display-table offset.

A rule contains source position(s), calendar lag(s), an operator and a target
predicate. Example operators already represented by VLA research engines include
concatenation, lộn, bộ, chạm and tổng.

For eligible target dates `t1...tn`, let `s_t` be the rule's success indicator.
The current run is the maximum r such that the final r eligible indicators are all
1. A max historical run is the maximum consecutive run anywhere in the chosen
historical segment.

A long run is pattern evidence only. Searching many positions creates selection
bias; hypothesis count, FDR/reality checks and untouched holdout must be recorded.

## 11. Two-nháy

For candidate x in one target draw let `c_x` be exact occurrence count among all
27 prize suffixes.

- ordinary Loto hit: `c_x >= 1`;
- two-nháy hit: `c_x >= 2`;
- exact count: `c_x`.

These are different targets and must never share a label silently.

## 12. Pascal-style deterministic transform

Independent implementation based on publicly observable behavior.

Given seed digits `r^(0)=(d1,...,dn)`:

`r^(k+1)_i = (r^(k)_i + r^(k)_(i+1)) mod 10`.

Repeat until a configured terminal width, commonly one or two digits in public
descriptions. Source-prize selection and terminal interpretation are parameters.
The transform itself makes no predictive claim and must be evaluated as a
challenger before any production use.

## 13. Fibonacci

The mathematical sequence is:

`F0=0`, `F1=1`, `Fn=F(n-1)+F(n-2)`.

As of 2026-09-02 the research pass did not identify a sufficiently stable public
Vietnamese lottery-history mapping to specify a canonical Fibonacci challenger.
VLA therefore does not invent one.

## 14. Challenger feature families

The current domain families are explicit, non-overlapping column allowlists:

- baseline;
- partner (canonical reverse/lộn partner);
- cap_50 (pair-level statistics for the 50-pair partition);
- bo;
- bong;
- cham;
- tong.

Additional research families such as dynamic pattern, conditional matrix, Markov,
graph, Pascal or Fibonacci must remain off by default until separately defined and
validated.

## 15. Controlled walk-forward ablation

For each fold:

`TRAIN < CALIBRATION < TEST` chronologically.

Baseline and challenger must share:

- train/calibration/test dates;
- labels/candidates;
- downsample indices;
- model hyperparameters;
- model seed;
- calibration method.

The only intended difference is challenger features/model specification.

VLA's domain challenger uses folds 1-2 for screening, fold 3 for individual
confirmation, and fold 4 as untouched combined holdout.

## 16. Draw-cluster bootstrap

Candidate rows inside one draw are correlated. Bootstrap unit = date/draw.

For each replicate sample OOS dates with replacement. A sampled date contributes
all of its candidate rows, repeated sampled dates retain multiplicity, and the
same sampled clusters are used for baseline and challenger.

Report paired improvements:

`delta_brier = baseline_brier - challenger_brier`

`delta_logloss = baseline_logloss - challenger_logloss`.

A 95% percentile interval is computed from deterministic bootstrap replicates.

## 17. Production promotion gate

The domain feature gate fails closed. A family must first survive chronological
screening and independent confirmation. The combined candidate then reaches the
final holdout.

Production does not tune trust on that holdout. A fixed configured trust is used
to form the exact blend that would be served:

`p_prod_raw=(1-w)*p_baseline + w*p_challenger`.

For Đề this raw 100-number vector is normalized exactly as in serving before
categorical scoring.

Promotion requires:

1. sufficient OOS dates;
2. production-blend Brier skill > 0;
3. production-blend LogLoss skill > 0;
4. Brier improvement CI lower bound > 0;
5. LogLoss improvement CI lower bound > 0;
6. finite metrics/CI;
7. valid temporal partitions.

Any unknown/NaN/bootstrap failure or insufficient history rejects promotion.

## 18. Production feature firewall

Production features are serialized explicitly:

```json
{
  "schema_version": 2,
  "baseline_features": [],
  "feature_groups": {},
  "promoted_groups": [],
  "production_features": []
}
```

Inference passes only the ordered `production_features` columns to the model.
Extra/rejected columns in a DataFrame are inert. Inactive challengers retain the
baseline feature list and zero trust.

## 19. Selection-bias warning

Repeated testing of windows, operators and feature groups on the same historical
holdout can overfit the evaluator itself. `PATTERN_SELECTION_BIAS_RISK` applies
whenever the same evaluation period is reused for selection or reported proof.
Longer-lived shadow validation or preregistered future holdouts are preferred for
future promotion decisions.
