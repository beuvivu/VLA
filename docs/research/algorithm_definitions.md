# Canonical algorithm definitions and safety contract

Last verified: 2026-09-02

Historical patterns do not guarantee future lottery outcomes. Only temporal
out-of-sample evidence may justify enabling an experimental feature in
production.

## Data and time semantics

VLA keeps the following concepts separate:

| Layer | Meaning | Representative implementation |
| --- | --- | --- |
| RawDraw | Published prize values with their original widths | `lottery.Result`, raw dataframe |
| NormalizedDraw | Date, semantic digit positions, 00..99 occurrence multiplicity, special suffix | `dynamic_cau.NormalizedDraw` |
| CandidateObservation | One `(anchor date, candidate)` training row | `cau_keo_ml.build_cau_keo_feature_frame` |
| DerivedFeature | Value computable from information available at/before the anchor | `ml_features`, domain augmentation |
| PatternEvidence | Historical rule support, failures, streaks and search diagnostics | `dynamic_cau.PatternEvidence` |
| ModelPrediction | Calibrated model probability emitted for a future target | serialized cầu-kèo model/output |

For target date `D`, descriptive/research APIs in this tranche use only rows
with `date < D`. Training rows use anchor `t` to predict target `t+1`.
`calendar_alignment` rejects duplicates and supplies exact-calendar pairs.
Raw positional history and normalized two-digit history must have identical
ordered date axes before ML features are built.

## Canonical number ontology

`number_reference.py` is the single source of truth. Do not reimplement these
rules in feature modules.

- head and tail are the tens and units digits;
- raw digit sum is 0..18; total-mod-10 is `(head+tail) mod 10`;
- reverse/lộn maps `AB` to `BA`;
- bóng dương digit mapping is `0↔5, 1↔6, 2↔7, 3↔8, 4↔9`;
- bộ is the orbit generated by bóng dương and reverse;
- cặp Loto 50 is 45 reverse pairs plus `00-55`, `11-66`, `22-77`,
  `33-88`, `44-99`;
- chạm `d` is the 19-number set containing `d` in either position;
- doubles, lệch/âm variants, and linear/circular sát-kép variants are explicitly
  distinguished.

These are deterministic domain relations, not predictive claims.

## Frequency

Given eligible draws `W_D` strictly before `D`:

```text
occurrence_count(x) = Σ[t in W_D] count_t(x)
draw_count(x)       = Σ[t in W_D] 1[count_t(x) > 0]
hit_rate(x)         = draw_count(x) / |W_D|
```

`frequency_stats.compute_frequency_stats` exposes both counts and never uses
one as an alias for the other. Calendar and draw-count windows are mutually
exclusive configuration choices.

```python
stats = compute_frequency_stats(sparse, "2026-09-03", lookback_days=30)
```

## Gap and recurrence

If the most recent hit index before `D` is `i_last` and `n` draws are eligible:

```text
current_gap_draws = n - i_last - 1
```

For consecutive hit indices `i_(k-1), i_k`:

```text
interval_draws = i_k - i_(k-1)
absent_draws   = interval_draws - 1
```

`gap_cycle_stats.compute_gap_stats` also reports calendar units, completed-gap
mean/median/max, empirical current-gap percentile, z-score when variance is
defined, interval quartiles, recent interval slope, and current censoring.
Current censoring is not silently inserted as a completed recurrence.

Long gaps are descriptive. A larger gap does not imply a higher next-draw
probability unless a separately evaluated model demonstrates that relationship.

## Group statistics

`compute_group_frequency_stats` and `compute_group_gap_stats` accept `head`,
`tail`, `total_mod10`, or `cham`. Occurrence count sums member multiplicity;
draw count is the number of dates containing any member. Chạm groups overlap by
design.

## Two-nháy semantics

VLA stores these separately for each individually predicted number:

```text
ordinary Loto hit = occurrence_count >= 1
two-nháy hit      = occurrence_count >= 2
exact count       = occurrence_count
```

For a multi-number prediction set, two different one-hit candidates are not
pooled into a two-nháy success. `PatternEvidence` reports at-least-one,
at-least-two, and an exact-count histogram.

## Dynamic positional pattern engine

A source position has semantic identity:

```text
(prize_name, result_index, digit_index)
```

It never depends on a rendered table offset. A lag-one rule reads positions
from the exact previous calendar draw and applies one of:

- `concat`: `a,b -> 10a+b`;
- `reverse_concat`: `a,b -> 10b+a`;
- `reverse_pair`: `{10a+b,10b+a}`;
- `bo`: canonical bộ containing `10a+b`.

```python
result = find_running_patterns(
    raw_history,
    days_count=3,
    source_positions=[position_a, position_b],
    transformations=["concat", "reverse_pair"],
    target_type="loto",
    minimum_support=30,
    max_hypotheses=50_000,
)
```

The result records the complete search-space size, hypotheses actually searched,
survivors, active/longest streaks, support, successes/failures, raw and Laplace-
smoothed confidence, coverage and recent hit dates. Searching more than one
hypothesis sets `PATTERN_SELECTION_BIAS_RISK`. A long historical run is pattern
discovery, not OOS evidence.

## Co-occurrence, transitions, and association rules

For eligible observations `N`:

```text
support(A -> B)    = count(A and B) / N
confidence(A -> B) = count(A and B) / count(A)
lift(A -> B)       = confidence(A -> B) / P(B)
```

`conditional_matrices.build_cooccurrence_matrix` uses same-draw sets.
`build_transition_matrix` uses only exact next-calendar-day pairs. Both retain
raw counts and marginal support. Because Loto is multi-label, each target
number is a Bernoulli outcome and its smoothed conditional rate is:

```text
(count(A and B) + alpha) / (count(A) + 2*alpha)
```

Rows are not forced to sum to one. `association_rules.mine_association_rules`
adds minimum evidence filters and a Wilson lower confidence bound so `1/1`
does not outrank `70/100` solely on raw confidence.

## Exclusive-state Markov chain

For mutually exclusive state space `S`:

```text
P_ij = (count(i -> j) + alpha)
       / (sum_k count(i -> k) + alpha*|S|)
```

`markov_stats.build_markov_chain` retains counts and verifies normalized rows
under positive smoothing. The existing `compute_markov_for_loto` instead models
same-number hit/miss Bernoulli transitions, which is appropriate to multi-label
Loto. `number_dynamics` contains limited second-order research features with
shrinkage. None are promoted merely because they fit history.

## Candidate score versus probability

`candidate_scoring.rank_candidates` returns a ranking score:

```text
score(x) = Σ available_i weight_i * normalized_component_i(x)
           / Σ available_i weight_i
```

Default nonzero components are frequency, recency and EMA. Gap-percentile and
cycle components exist but default to zero to avoid embedding a gambler's-
fallacy assumption. Conditional and pattern inputs are optional and default
off. Optional inputs must already be normalized to `[0,1]`; invalid scales fail
configuration validation. Missing weighted optional inputs are disclosed and
excluded.

EMA is:

```text
alpha = 2 / (span + 1)
EMA_t = alpha*y_t + (1-alpha)*EMA_(t-1)
```

The configuration records span, minimum history, and initialization (`zero`,
`first`, or `historical_mean`). `CandidateScore.score` is never presented as a
calibrated probability. A model probability must come from a fitted and
evaluated probabilistic model.

## ML feature families and production manifest

The established production baseline in `cau_keo_ml.py` remains the champion.
The existing domain challenger has explicit groups:

| Group | Source of truth | Default production state |
| --- | --- | --- |
| baseline | `cau_keo_ml.FEATURE_COLS` | enabled |

The gate artifact embeds an explicit feature manifest:

```json
{
  "schema_version": 1,
  "baseline_features": [],
  "feature_groups": {},
  "promoted_groups": [],
  "production_features": [],
  "evaluation": {}
}
```

Production inference calls `predict_with_feature_allowlist`; rejected columns
are never passed to the model. Regression tests mutate a rejected feature to
extreme values and require unchanged predictions.

## Walk-forward and promotion gate

The domain experiment has four chronological validation folds:

1. screen groups on folds 1–2;
2. confirm survivors on later fold 3;
3. combine confirmed groups and evaluate once on untouched fold 4;
4. compare baseline and challenger with identical dates, labels, candidates,
   hyperparameters, and seed.

For each loss:

```text
improvement = baseline_loss - challenger_loss
skill       = improvement / baseline_loss
```

Brier score and LogLoss are losses, so positive improvement/skill is better.
Uncertainty uses a paired clustered bootstrap: sample OOS dates with replacement,
keep every 00..99 row for each sampled date, preserve repeated sampled dates,
and recompute both losses. Default settings are 1,000 replicates, seed
`20260902`, 95% intervals and at least 30 OOS dates.

Promotion requires all of:

- strict temporal partition checks pass;
- sufficient OOS dates;
- Brier skill exceeds the configured positive threshold;
- LogLoss skill exceeds the configured positive threshold;
- Brier improvement lower CI is greater than zero;
- LogLoss improvement lower CI is greater than zero;
- all states and metrics are finite/valid.

The gate fails closed with explicit reasons such as
`negative_brier_skill`, `negative_logloss_skill`,
`brier_ci_crosses_zero`, `logloss_ci_crosses_zero`,
`insufficient_oos_dates`, or `temporal_leakage`. If no challenger passes,
baseline probabilities are unchanged.

## Pascal, Fibonacci, and graph status

The public Pascal recurrence observed in this review is an adjacent-sum modulo-
10 triangle. Its seed and candidate extraction were not specified robustly
enough for independent replication, so it is documented and rejected rather
than guessed. Fibonacci's standard recurrence is known, but no reproducible
lottery-history mapping was found. Graph summaries remain planned descriptive
research on canonical matrices. None enter production.
