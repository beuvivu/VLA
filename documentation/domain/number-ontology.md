# Canonical number ontology

VLA separates deterministic number relations from statistical co-occurrence so
that Vietnamese lottery terminology does not create ambiguous data fields. A
term being part of the ontology does **not** mean that it has predictive power;
predictive weight must be established by leakage-safe validation.

The implementation source of truth is `src/number_reference.py`. Feature modules
must not reimplement these rules locally.

## Canonical/domain conventions

- **Lộn / đảo**: `AB -> BA`.
- **Bóng dương digit**: `0<->5`, `1<->6`, `2<->7`, `3<->8`, `4<->9`.
- **Bóng dương 2D**: apply the bóng-dương map to both digits.
- **Bóng âm digit** (documented domain convention): `0<->7`, `1<->4`,
  `2<->9`, `3<->6`, `5<->8`.
- **Cặp loto 50**: a complete partition of `00..99` into exactly 50 pairs:
  45 reverse pairs `AB-BA` plus five **cặp kép bóng**:
  `00-55`, `11-66`, `22-77`, `33-88`, `44-99`.
- **Cặp kép bóng**: the five pairs of kép bằng whose repeated digit is the
  bóng-dương digit of the other repeated digit. These pairs share domain-level
  evidence, but VLA must not force their two probabilities to be equal.
- **Bộ / hệ**: the bóng-dương + lộn orbit. The 100 numbers partition into exactly
  15 unique families: 10 **bộ thường** of 8 numbers and five **bộ kép** of 4.
  Conventional family IDs are:
  `00,01,02,03,04,11,12,13,14,22,23,24,33,34,44`.
- Example **bộ 01**: `01,10,06,60,51,15,56,65`.
- Example **bộ kép 00**: `00,55,05,50`.
- **Cặp số (generic)**: any unordered pair of two 2D numbers. It does not imply a
  reverse, bóng or bộ relationship.
- **Cặp lộn**: the deterministic relation between `AB` and `BA`.
- **Same-draw co-occurrence pair**: a statistical observation that two distinct
  loto numbers appeared in the same draw. It is stored separately from the
  deterministic 50-pair system.
- **Kép bằng**: `00,11,22,33,44,55,66,77,88,99`.
- **Kép lệch dương**: `05,50,16,61,27,72,38,83,49,94`.
- **Kép âm** under the documented bóng-âm convention:
  `07,70,14,41,29,92,36,63,58,85`.
- **Chạm d**: all two-digit numbers containing digit `d`; each chạm contains 19
  unique numbers.
- **Tổng d**: `(head + tail) mod 10 == d`; each tổng contains 10 numbers.
- **Sát kép**: the repository keeps a linear-adjacent and an explicitly named
  circular-adjacent variant. These variants must not be mixed silently.

## Statistical treatment

The common 50-pair partition is useful for feature engineering because it gives
every number exactly one partner. VLA distinguishes three different quantities:

1. **individual evidence** — frequency, gap, hazard, path support and ML evidence
   for one number;
2. **shared pair evidence** — any-member frequency, both-member frequency,
   partner frequency/gap, pair balance and pair-level recency;
3. **pair relation type** — `reverse` or `kep_bong`.

For `00-55`, `11-66`, `22-77`, `33-88`, `44-99`, shared evidence may support a
similar cầu-kèo assessment. This is a *prior/feature relationship*, not an order
to make the two numbers identical. Any production regularization must first beat
the unregularized model on untouched chronological validation data.

Signals such as **gan, bệt, câm, rơi, trùng cầu, trùng bộ, tổng thiếu, chạm
thiếu** are descriptive/research features. Their names may be retained for
explainability, but no predictive weight is granted merely because a folklore
rule exists.

## Provenance and confidence

The canonical ontology is a software/data contract, not a claim that folklore
relationships have predictive power. VLA adopts a domain relationship only when
it is repeated consistently across independent Vietnamese lottery-reference
sources **and** can be represented as a deterministic mapping.

The five kép-bóng pairs are recorded as a shared domain relation because common
cặp-loto tables explicitly use them to complete the 50-pair partition. VLA does
not infer that the two members must have equal probability. Historical balance,
co-occurrence, recency and downstream predictive value are measured separately.

Some terms remain **variant-sensitive**, particularly the detailed definitions of
sát kép / sát kép lệch and narrative patterns such as bệt, câm, rơi, trùng cầu,
bạc nhớ or nuôi khung. They may be represented as explicitly named research
features but do not receive production weight without chronological validation.

Per-source observations and the method-level comparison matrix are recorded in
[`../research/source-comparison.md`](../research/source-comparison.md).

## Data artifacts

`data/reference/` is regenerated by the production pipeline:

- `number_ontology_00_99.csv` — one row for each number `00..99`, including its
  reverse, bóng dương, bóng âm, 50-pair partner and bộ family.
- `bo_seed_catalog_00_99.csv` — all 100 lookup labels and canonical family IDs.
- `bo_unique_families.csv` — exactly 15 unique families, labeled `bo_thuong` or
  `bo_kep`.
- `cap_loto_50.csv` — exactly 50 pairs: 45 `reverse` + five `kep_bong`.
- `manifest.json` — schema and terminology contract.

`data/pairs/` contains empirical statistics for the 50-pair system, including
member rates, pair any/both rates, Jaccard, phi, current gaps and rolling
30/90/365-day member-balance measures. These statistics are evidence for later
model validation, not guaranteed forecasting rules.

## Excel integrity

Lottery prize codes in Excel are **text values**, not numeric cells with cosmetic
formats. Exact widths are mandatory:

| Prize | Width |
| --- | --- |
| Đặc biệt / G1 / G2 / G3 | 5 digits |
| G4 / G5 | 4 digits |
| G6 | 3 digits |
| G7 | 2 digits |

Every export is reopened immediately and checked. CI additionally compares every
Excel prize cell back to `data/xsmb.csv`, including all 27 prize values in the
latest daily workbook. A missing leading zero, missing prize, wrong width, dirty
token, or wrong value fails the integrity gate.
